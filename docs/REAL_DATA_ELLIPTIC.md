# Real data: Elliptic Bitcoin dataset (labeled)

Generated by `npm run evaluate:elliptic` on 2026-10-30, TigerGraph Savanna TG-00, graph `GhostShieldGraph`.

**Data.** Weber et al., *Anti-Money Laundering in Bitcoin: Experimenting with Graph Convolutional Networks for Financial Forensics*,
KDD Workshop 2019. 203,769 Bitcoin transactions (nodes), 234,355 payment-flow edges,
4,545 illicit and 42,019 licit labels (the rest unknown). Real labels, real topology.
A transaction is modelled as a `Wallet` vertex. The dataset has no amounts or addresses, so edges have weight 1 and time is the dataset's
49 two-week steps. Raw files are not redistributed (see REAL_DATA.md).

**Protocol (no leakage).** A random 50% of the illicit labels are known-bad seeds. The remaining illicit labels (held out) and all licit labels form
the test set. The engine ranks wallets by propagated taint; wallets the taint never reaches score 0 (ties count as half). Unknown-class
nodes are never scored. 3 random splits, mean ± sd. Base rate of held-out illicit in the test set: **5.1%**.

## Sanity check: cycle detection on a DAG

The Elliptic transaction graph is a directed acyclic flow graph. The temporal cycle detector reported **0** cycles (4118 ms), as it should.

## Findings (computed from the table above)

* **Overall ranking (AUC), at equal hop horizons:** 2 hops: GhostShield 0.810 vs unweighted distance 0.802 (+0.008); 4 hops: GhostShield 0.861 vs unweighted distance 0.838 (+0.023); 6 hops: GhostShield 0.887 vs unweighted distance 0.849 (+0.038); random = 0.498.
* **Top of the ranking (precision@100):** best GhostShield variant 18.0% vs best baseline 43.7% — **the engine is worse than the naive rule at the very top**. A plausible but untested reason: without amounts, the haircut reduces to degree normalisation, which favours low-degree, chain-like neighbours.
* **Direction:** one-directional propagation reaches AUC 0.576 / 0.578 (forward / backward), close to random; propagating in both directions reaches 0.810 / 0.861 / 0.887 at 2 / 4 / 6 hops. Illicit transactions are associated with seeds both upstream and downstream.
* **Coverage trade-off:** at 6 hops the method reaches 94% of held-out illicit but also 64% of licit transactions; at 2 hops it reaches 66% / 6%.
* **Engine correctness cross-check:** at 2, 4 and 6 hops the set of wallets the engine reaches (share of held-out illicit and of licit with a non-zero score) is identical to an independent client-side BFS from the same seeds.

## What this does and does not show

* It is a structure-only method: no transaction features are used. It is **not** comparable to supervised classifiers on this dataset (the
  paper's random forest uses 166 anonymised features per node).
* Elliptic has **no amounts**, so every edge has weight 1 and the "haircut by amount share" reduces to dividing by a transaction's degree.
  This dataset therefore does **not** test the value-weighting that the algorithm was designed around; that part is untested on real data.
* Seeds are labeled illicit transactions; unknown-class nodes are ignored, and labels may themselves be noisy.
* One dataset, one chain (Bitcoin), 2019 data: external validity to Ethereum fraud or to current traffic is unknown.
