# GhostShield: Security Architecture & Operational Guardrails

## 1. Security Principles

GhostShield operates under the principle of **Defensive Graph Isolation**. It evaluates risk signals without maintaining cryptographic custody, executing mainnet signatures, or storing user private keys.

---

## 2. Threat Modeling & Controls

### 2.1 Credential Secrecy & API Boundary
* **Zero Client Leakage:** All external database credentials (`TIGERGRAPH_SECRET`, `TIGERGRAPH_PASSWORD`), AI tokens (`AIGI_API_KEY`), and notification endpoints (`VIASOCKET_WEBHOOK_URL`) reside strictly within server-side environment variables (`process.env`).
* **Next.js Server Isolation:** Next.js route handlers act as an authenticated reverse proxy. Client browsers communicate solely with GhostShield REST endpoints via JSON; client code never establishes direct TCP/HTTP sockets to TigerGraph or viaSocket.

### 2.2 GSQL Injection Prevention
* **Parameterized Query Invocation:** GhostShield never concatenates user-supplied strings into raw GSQL query definitions. All interactions with TigerGraph Cloud execute against **pre-compiled, installed queries** via the REST++ API (`/restpp/query/{graph}/{query_name}`) using strict type-cast query parameters:
  * `target_wallet`: `STRING` (sanitized and checked against address regex).
  * `time_window_seconds`: `INT` (clamped between $10$ and $86400$).
  * `max_depth`: `INT` (clamped between $2$ and $5$).

### 2.3 Denial of Service & Graph Memory Explosion
* **Bounded Traversal Depth:** Unbounded cycle detection or BFS on arbitrary graphs can result in combinatorial $O(V^k)$ explosions. GhostShield enforces:
  * Maximum cycle search depth of $k=4$.
  * Transfer edge limits ($N \le 25$) and neighbor limits ($N \le 50$) per hop.
  * Request timeout caps (TigerGraph: 8000ms, viaSocket: 4000ms, AI: 6000ms).

### 2.4 Simulation vs. Execution Boundary
* **No Mainnet Signing:** Any `ALLOW`, `REVIEW`, or `REJECT` action generated by GhostShield represents an advisory risk assessment. GhostShield possesses zero capabilities to sign, broadcast, or alter live blockchain transactions.
* **Deterministic Authorization:** Risk scoring ($0 \dots 100$) is computed mathematically by the server engine. LLMs are strictly confined to generating narrative explanations; an LLM completion cannot override or modify an authoritative `REJECT` or `ALLOW` decision.

### 2.5 Error Handling & Information Disclosure
* API route handlers catch database and network errors, logging full diagnostic details to server stdout while returning sanitized JSON error messages to the client. Stack traces and database connection strings are never exposed in production HTTP responses.
